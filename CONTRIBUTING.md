# Contributing to AgriMove

First off, thank you for considering contributing to **AgriMove**! It is people like you who make this framework a great tool for the global agricultural robotics community.

As an open-source project, we welcome contributions in many forms: from bug reports and documentation improvements to new AI models and motion planning algorithms.

---

## 🚀 How Can I Contribute?

### 1. Reporting Bugs
If you find a bug in the framework or simulation environment:
*   Open an **Issue** on GitHub.
*   Describe the bug clearly, including steps to reproduce it.
*   Mention your environment (e.g., ROS 2 version, OS, Hardware).

### 3. Pull Requests
If you want to contribute code:
1.  **Fork** the repository.
2.  Create a new **branch** for your feature or fix.
3.  **Commit** your changes with clear, descriptive messages.
4.  **Push** to the branch.
5.  Open a **Pull Request** (PR) against the main branch.

---

## 🛠 Technical Guidelines

To maintain high quality, we follow these standards:

*   **Framework Consistency:** All robotic nodes must be compatible with **ROS 2**.
*   **Motion Planning:** New manipulation logic should utilize the **MoveIt 2** API where possible.
*   **Coding Style:**
    *   **Python:** Follow PEP 8 standards.
    *   **C++:** Follow the ROS 2 C++ Style Guide.
*   **Simulation:** We encourage testing all new features in **NVIDIA Isaac Sim** or Gazebo before submitting a PR.

---

## 📝 Documentation
Documentation is as important as code. If you change how a module works, please ensure the README or the documentation folder is updated to reflect those changes.
